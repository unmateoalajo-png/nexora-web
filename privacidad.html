Política de privacidad

Última actualización del borrador: 22 de noviembre de 2026.

Borrador informativo; aprobación pendiente Este texto documenta hechos técnicos verificados, pero no se presenta como una política legalmente aprobada. Antes de su publicación final debe aprobarse la identidad legal del responsable y confirmarse los puntos señalados al final.

1. Alcance y uso de NEXORA

NEXORA es la marca pública de una herramienta personal y exclusiva para administrar el canal de YouTube de su propietario. No se ofrece a terceros, no permite crear cuentas y no tiene usuarios externos.

El sitio informativo propuesto es estático: no incorpora formularios, analítica, cookies propias de seguimiento ni SDK de terceros.

2. Responsable y contacto

La identidad legal de la persona responsable está pendiente de aprobación. “NEXORA” identifica la marca pública y no sustituye automáticamente el nombre de una persona natural o jurídica.

El canal de contacto es nexora.studio.ec@gmail.com. Ecuador es el país de referencia del proyecto; esta mención no confirma por sí sola domicilio, identidad legal ni jurisdicción aplicable.

3. Permisos OAuth e información tratada

NEXORA solicita únicamente estos permisos de Google:

  • youtube.upload: iniciar subidas reanudables de videos al canal propio y establecer sus miniaturas. Ya se realizaron subidas privadas.
  • youtube.readonly: leer el identificador del canal autenticado, su lista de subidas y datos de videos como identificador, título, descripción y estado de privacidad. Se utiliza para verificar el canal y evitar subidas duplicadas.
  • yt-analytics.readonly: consultar por video vistas, minutos vistos, duración media, porcentaje medio visto y suscriptores ganados. La función está implementada, pero no se ha confirmado su ejecución en producción.

NEXORA no solicita permisos de perfil ni correo de Google, ni el permiso general de administración de YouTube.

4. Finalidades

La información se utiliza para autenticar al propietario, verificar el canal conectado, subir contenido privado, asignar miniaturas, detectar versiones ya subidas y, si el propietario ejecuta la función correspondiente, generar métricas y alertas editoriales locales.

5. Autorización y revocación

La autorización se concede mediante la pantalla de consentimiento de Google. El propietario puede revocar el acceso de NEXORA desde la configuración de seguridad de su cuenta de Google. La revocación impide nuevos accesos con esa autorización, pero no elimina automáticamente archivos locales, secretos de GitHub, informes ya generados ni videos ya subidos.

6. Almacenamiento, conservación y eliminación

  • En el equipo del propietario puede existir un archivo OAuth local con el identificador y secreto del cliente, el token de actualización y la fecha de creación. Se crea con acceso restringido y está excluido del repositorio Git.
  • En GitHub Actions se utilizan secretos para el identificador del cliente, el secreto del cliente y el token de actualización. Los tokens de acceso se mantienen en memoria durante la ejecución y el código no los guarda en archivos.
  • Las consultas de métricas, cuando se ejecutan, se agregan a informes locales junto con alertas. No existe eliminación automática ni plazo de conservación definido para esos informes.
  • Los registros de Actions pueden contener identificadores y enlaces de videos privados. La política de retención de esos registros no está verificada.
  • Los artefactos de video, voz, renderizado y auditoría configurados en los workflows se conservan 1 día; los artefactos de miniaturas, 7 días.
  • Los tokens, secretos, informes locales y videos privados no tienen un plazo de eliminación definido. Los videos privados permanecen en YouTube hasta su eliminación manual.

No existe actualmente un proceso automatizado para revocar o rotar credenciales, borrar informes locales, eliminar secretos de GitHub ni eliminar videos de YouTube. Las solicitudes pueden enviarse al correo de contacto, pero el procedimiento y el plazo de respuesta todavía deben definirse y aprobarse.

7. Proveedores

El funcionamiento conectado utiliza Google OAuth, YouTube Data API y YouTube Analytics API. También utiliza GitHub Actions, GitHub Secrets, runners alojados por GitHub, registros y almacenamiento temporal de artefactos. La auditoría no identificó una ruta que enviara tokens o respuestas de las API de Google a otros proveedores usados para producir recursos editoriales.

8. Seguridad

Entre las medidas verificadas se incluyen PKCE S256, estado aleatorio contra solicitudes falsificadas, retorno OAuth limitado al equipo local, archivos OAuth excluidos de Git, acceso restringido al archivo local, secretos enmascarados en los registros revisados, permisos de GitHub limitados, acciones fijadas a revisiones concretas y controles que mantienen deshabilitada la publicación pública salvo condiciones expresas. Estas medidas reducen riesgos, pero no garantizan seguridad absoluta.

9. Datos de Google

El uso de información recibida de las API de Google debe mantenerse coherente con la Política de Datos de Usuario de los Servicios API de Google, incluidos sus requisitos de uso limitado cuando sean aplicables.

10. Cambios

Los cambios materiales deberán reflejarse en esta página mediante una nueva fecha y una descripción actualizada de las prácticas reales. No se afirma todavía un mecanismo adicional de notificación.
